# npm supply-chain incidents, 2025–2026: which releases were malicious and what caught them

One page per incident. Each page has what the attack changed compared with the package's previous release, the exact malicious versions with their OSV ids, how pkgdelta and [GuardDog](https://github.com/DataDog/guarddog) did on them, and how to check your own lockfile.

The numbers come from the files in [`results/`](../../results). The tables inside each page are generated by [`corpus/incident_tables.py`](../../corpus/incident_tables.py); the text around them is written by hand.

How to read the columns:

- **pkgdelta v1 (frozen)** is the rule set committed before any 2026 data was run. For 2026 incidents it is a blind test.
- **pkgdelta v2** was changed after seeing the 2026 misses. On 2025 and early-2026 incidents it is not a blind test. On [ChainDrop](chaindrop-keyv.md) (August 2026) it is.
- The 2025 incidents (Nx, chalk/debug, both Shai-Hulud waves) are training data: the rules were written while looking at them.
- **GuardDog `high_risk`** is GuardDog 3.2.0's own top verdict, on the malicious version alone (it has no compare-with-previous mode). "of N" is how many it could scan.

## Check your lockfile

```
pip install git+https://github.com/thejusdutt/pkgdelta
pkgdelta audit package-lock.json      # or pnpm-lock.yaml / yarn.lock
```

`audit` compares every locked version with the release before it and asks [OSV](https://osv.dev) whether it is known malware, so versions npm has since deleted still fail.

Method and the full evaluation: [evaluation.md](../evaluation.md). What each rule looks for: [rules.md](../rules.md).
